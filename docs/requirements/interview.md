## 2026-10-25 交付指令与实现范围

**本轮已确认：** 产品定位为现有 Agent Harness 的轻量可视化编排平台；自动发现当前环境安装的 Agent，提供左右脑卡片与连接、自然语言输入、真实编程/审查/测试/修复循环，以及 Prompt、Session、工具事件和结果可观察性。用户要求复用成熟能力、持久化 Checkpoint/Handoff、实际部署且不能伪造执行，明确要求将代码推送到 `https://github.com/0ilyCat/ramune-harness`，不再暂停询问常规技术与产品决策。

**自主落实的首版选择：** Windows 原生与 WSL Ubuntu 为双环境，服务仅绑定 loopback；采用 React Flow + Hono + Zod + Execa。Codex 与 Claude Code 使用官方非交互 CLI 协议，复用原生登录、权限与工具循环。左右脑使用独立新 Session，以前一节点输出显式交接，不自动复用历史 Session。模板由构建、审查、独立检查与输出组成，审查拒绝或检查失败回到构建节点。可配置有界调用预算和运行超时。

**边界与待验证项：** 内部工具调用是 Harness 原生事件，首版不将每个工具展开为独立可配置卡片，不实现能力边绑定、任意插件热加载、并发图、组合子图编辑、公网多租户或桌面安装包。Gemini CLI/OpenCode 只发现安装，不冒充已接入。平台实际覆盖与验收证据见 `docs/delivery.md`，未完成项必须如实记录。

规格和持久交接位于 `.scratch/autonomous-build/`。历史文档中的“当前不实现”由本轮明确实现授权取代。

## 已确认的设计原则

- 极小内核与可插拔卡片；一切执行能力以节点承载，智能能力可选。
- 可视化工作流，节点具有明确的输入、输出和数据约束。
- 节点可启用、关闭与组合；循环、记忆与工具能力可选。
- 可以提供规划、生成、评估等组合卡片；首版提供哪些组合仍需按验收场景裁剪。
- 优先复用成熟开源组件，MVP 简单优先。
- 当前不编写业务实现代码，所有文档使用中文。

### 第 1 轮已完成

**Q1：执行形态。** 用户选择推荐项：顺序控制流，每次只执行一个节点，由明确的路由决定下一步；数据由端口和映射传递。首版延后并行与汇合。

**Q2：工具连接。** 用户选择推荐项：执行连接驱动流程，能力连接声明智能体可使用哪些工具，不因连接存在而直接执行工具。实际工具调用仍作为节点执行接受输入输出校验、权限控制与追踪；能力绑定不等于授权。

**Q3：首个验收场景。** 用户选择推荐项：修改指定本地项目，运行检查，成功停止、失败后有界修正。同时用一个无模型流程验证智能可选；完整自主开发延后。

用户回复“全部推荐”，仅确认本轮 Q1—Q3。

### 第 2 轮已完成

**Q4：上下文与记忆。** 用户选择 A：区分本次任务的显式运行上下文与可选的跨运行记忆。模型节点不自行保存会话，工具结果、计划与消息仅通过工作流声明的输入组装；移除 Memory 后不自动读取历史任务或旧会话，本次检查错误仍可显式送回修正节点。运行记录不能自动成为模型上下文。

**Q5：循环与停止。** 用户选择 A：显式循环入口与回边，设置有限迭代上限，由检查结果和条件路由决定继续或退出；编程闭环通过与否由配置的检查决定，耗尽预算属于未完成。取消、超时和执行预算属于通用运行约束，不要求工作流包含 Loop 节点。

**Q6：恢复强度。** 用户选择 A：保存工作流版本和已完成节点调用结果，在调用边界由用户确认后继续；结果未知的文件修改或命令执行先检查，不自动重放。具体保存字段和持久化协议仍需设计与验证。

用户于 2026-10-14 回复“全部推荐”，确认本轮 Q4—Q6。

### 第 3 轮待回答

**Q7：平台与启动。** 推荐首版优先支持 Windows，通过本地命令启动服务，在浏览器使用编辑器；macOS/Linux 后续验证，桌面安装包延后。备选为首版跨平台浏览器应用，或立即提供桌面安装包。用户当前环境是 Windows，但平台优先级不能据此视为已确认。

**Q8：本地操作授权。** 推荐启动运行时确认工作目录、文件修改能力和预配置检查命令；模型提出的额外命令逐次确认。备选为启动时授权整个运行任意 Shell，或连文件修改和预配置检查也逐次确认。工作目录只限定受控工具的操作范围，不能当作任意 Shell 或本机插件的安全沙箱；密钥仅由后端读取，不写入工作流和导出的运行记录。

**Q9：第三方节点。** 推荐仅加载用户明确配置的可信本地插件，在启动时注册，新增插件后重启；节点描述含类型、版本、Schema 和执行入口。备选为首版支持运行时安装与热加载，或暂时只允许内置节点。插件是本机可信代码，应用层授权不约束恶意插件；插件市场、不可信代码隔离与运行中替换延后。

以上是建议，尚未确认。

## 建议的验证方式

- 能力连接是否比展开全部工具调用更容易理解：使用同一个编程任务对比两张图和逐次工具追踪视图，优先原型验证交互，而非争论抽象名称。
- 移除记忆后是否还携带隐式历史：后续用确定输入对照实际模型请求，检查历史是否仅来自显式输入；运行记录与模型上下文不能自动混用。
- 组合卡片和节点配置是否简单：在语义确认后，以规划、生成、评估卡片做界面原型，验证默认字段、端口和展开检查路径。
- 崩溃恢复是否遵守调用边界：后续通过故障注入验证完成结果持久化、循环中的调用身份、结果未知的副作用及人工继续，不宣称恰好一次执行。
