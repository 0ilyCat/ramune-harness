# 领域文档

项目采用单上下文布局。文档位于 `docs/`，术语表位于仓库根目录。

## 探索前阅读

- 阅读根目录 `GLOSSARY.md`，了解领域术语。
- 阅读 `docs/adr/` 中与当前工作相关的架构决策记录。

文件尚不存在时，直接继续工作。领域术语或决策明确后，由 `domain-modeling` 技能按需创建对应文档。

## 目录与职责

- `GLOSSARY.md`：项目共享术语。
- `docs/adr/0001-<decision-slug>.md`：按顺序编号的架构决策记录。
- `docs/research/`：研究证据与建议；建议经确认后才成为决策。
- `docs/requirements/`：需求访谈与后续需求规格。

文档标题、正文和说明使用中文；文件路径、产品名与技术标识符保留原文。

## 使用一致的术语

任务标题、设计建议、假设和测试名称采用术语表中的用词。需要的概念尚未记录时，先检查是否引入了项目未使用的说法，或将真实缺口交由领域建模处理。

## 说明决策冲突

建议与既有架构决策冲突时，明确指出相关 ADR，并说明重新讨论该决策的原因。
